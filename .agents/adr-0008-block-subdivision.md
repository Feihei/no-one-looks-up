# ADR-0008: 街区内部细分（两级路网）

状态：已实现（2026-11-17，R3.18；三类型一次落地，参数表分发等价于分阶段合并；实机验收待 Feihei）

日期：2026-11-16

## 上下文

ADR-0002 的 Block 优先生成把地图划成 50 m 格子的合并街区，街道是街区之间的负形。这套算法在比例上站得住，但**路网的空间频率被一个常量锁死了**：`CELL_SIZE = 50`。

后果是玩家走过整张图只看到一种街道间距：

- 相邻两个街区中心至少隔 50 m，路网节奏均匀到没有意外；
- 老城/城中村这类 1×1 街区（占面积七成以上）内部**一个岔口都没有**：格子均匀意味着要么整块不切、要么切就切满全图，玩家沿街走只遇到等距的十字路口；
- 城中村（R3.17）虽然把街宽压到 2.0-3.5 m，但**巷距仍是 50 m**——巷子很窄、街区很大，和实地"外墙 3-4 m、路口间距 6-10 m"的密度相差一个量级。

实测（2026-11-16，三个 seed）确认了"T 只在合并块边界"这一点：度为 3 的节点占 38–46%，但全部来自 2×2 公寓块 / 4×4 厂房块这类合并体的边界，尺度是 100–250 m；50 m 常规街区内部没有任何 T。

2026-11-15 实地踩点后提出的诉求很明确：先用较宽的道路分大块，大块内部再用小路细分，细分数量随机，允许出现 T 形路口，让路网更接近真实城中村。

## 决策

**保留 50 m 格子作为 tier-0 骨架，在街区内部增加一层子地块（sub-block）细分。** 不引入第二套坐标系，不改 `CELL_SIZE`。

### 两级路网

| 层级 | 位置 | 宽度 | 间距 | 产生方式 |
|---|---|---|---|---|
| tier 0 | 街区之间 | 6-10 m（现状） | 50-250 m（随合并规模） | `path_network` 现有逻辑，不变 |
| tier 1 | 街区内部 | 2.4-6 m | 10-46 m（按街区类型） | 新增细分 pass |

### 关键洞察：放置系统已经是图驱动的

`placement::plan_chunk` 遍历 `graph.edges`，靠 `edge.left_block` / `edge.right_block` 决定往哪侧放建筑——**不是**按固定格子放置。`collision` 按 `graph.blocks[].polygon` 生成棱柱，`debug_viz`/`minimap` 也读图。

所以只要细分产生**真实的 `LayoutBlock` + `LayoutEdge`**，下游放置、碰撞、渲染**零改动**。这是本方案成本可控的根本原因。

### 数据结构

```rust
/// 子地块：一个街区内部由巷道切出的一块地。
pub struct SubBlock {
    /// 父街区 id（`LayoutBlock::id`）。
    pub parent: u32,
    /// 子地块多边形（已 inset 到巷道边缘，世界坐标，CCW）。
    pub polygon: Vec<Vec2>,
    /// 朝向巷道的立面方向（建筑沿它贴线）。
    pub frontages: Vec<SubFrontage>,
}

/// 子地块的一条临巷边界。
pub struct SubFrontage {
    pub a: Vec2,
    pub b: Vec2,
    /// 巷道中心线到这条边的距离（= 巷道半宽）。
    pub lane_half_width: f32,
}
```

`LayoutBlock` 增加一个字段：

```rust
pub struct LayoutBlock {
    // ... 现有字段 ...
    /// 内部细分结果；空表示该街区不细分（厂房/广场/树林）。
    #[serde(default)]
    pub children: Vec<SubBlock>,
}
```

`LayoutEdge` 增加 `kind`，把巷道和街道区分开（供小地图、调试配色、以及放置侧的密度选择使用）：

```rust
pub enum EdgeKind {
    /// tier 0：街区之间的街道（现状行为）。
    Street,
    /// tier 1：街区内部的巷道。
    Lane,
}
```

### 细分算法（确定性与 T 路口的来源）

按街区类型决定细分强度，厂房 / 广场 / 树林不细分：

| 街区类型 | 巷道间距目标 | 巷道宽度 | 临巷地块长度 |
|---|---|---|---|
| 城中村 | 13 m（10-16） | 2.4-3.2 m | 11 m |
| 老城 | 24 m（16-30） | 3.5-5.0 m | 18 m |
| 公寓 | 46 m（30-60） | 5.0-6.0 m | 30 m |
| 厂房 / 广场 / 树林 | 不细分 | — | — |

单个街区的细分步骤：

1. 取街区 inset 后的多边形（现有 `block.polygon`）；
2. 随机选细分主轴（长边优先，30% 概率翻转，避免全图单向条纹）；
3. 沿主轴按目标间距切出若干房排（每排深度 7-9 m），房排之间是贯通巷道；
4. 沿次轴把每条房排切成独立地块（长度按上表随机 0.6-1.4 倍），**地块之间紧邻无缝隙**——贴线感由 `BuildingParams.spacing`（城中村 0.0）和 `setback`（0.25 m）表达，不由子地块留缝表达；
5. **巷道只在房排之间贯穿，不在房排内部打散切口**——每条巷都贯通整个街区的一端到另一端；
6. 巷道两端停在街区边界，与 tier-0 街道相接处就是 **T 形路口**。

第 4 条容易做错：如果地块之间留缝，房子之间会出现肉眼可见的窄槽，比"贴线"错得多。真实的城中村是墙贴墙，只有排水缝（0.25 m setback）和零星拆除后的空档。第 5 条是本方案与 2026-11-16 的 Python 原型的关键差别——原型在每条房排内部做了随机切口，切出来的短巷两端都不连通，渲染出来是一片**碎片状的死胡同**（见"备选方案"一节的记录）。

### T 形路口的产生机制

这是本方案最重要的收益，值得单独说明，也需要先纠正一个直觉误区。

**现状并非"没有 T 路口"**。实测三个 seed 的真实图：度为 3 的节点占 38–46%（seed 0x1: 38%，0x7: 46%，0x48454144: 43%），绝对数量 78–89 个。这些 T 来自**合并大块**的边界——一个 2×2 公寓块或 4×4 厂房块只占格网的一段，它的边界处街道自然提前终止。

问题不在数量，在**位置与尺度**：

- 所有 T 都贴着合并块（公寓/厂房）的边界，也就是 100–250 m 尺度；
- **50 m 常规街区内部一个 T 都没有**——那里要么是整块不切，要么切就切满，因为格子均匀；
- 因此玩家走在老城/城中村里（占全图 70%+ 面积的一格块），看到的永远是等距十字路口。

细分之后，T 会出现在**步行尺度**上：每条约 13-24 m 间距的巷道两端各撞一个 T，玩家每隔十几米就会遇到一个岔口，而不是每 50 m 遇到一个十字。这才是"接近真实"的来源——不是 T 的总数变了，而是 T 第一次进入了玩家实际行走的空间频率。

相邻街区各自独立细分，主轴方向和切分位置互不对齐，因此一条巷道在街区边界处不会延续到隔壁街区，而是撞上 tier-0 街道终止。这就是细分必然产生 T 的机制。

2026-11-16 的原型实测：435 个巷道端点与 tier-0 街道相交（687 个地块、719 段巷道）。

### 下游影响

| 系统 | 影响 |
|---|---|
| `placement` | 图驱动，天然适配。城中村仍按 `BuildingParams::UrbanVillage` 放置；细分后临巷地块更小，`usable_frontage` 与 `oriented_rect_inside_polygon` 直接作用于子地块多边形 |
| `collision` | 每个子地块一个凸棱柱（原来是每街区一个）。棱柱数量上升，`CollisionIndex` 的按 chunk 分桶保持不变；城中村一个 50 m 街区细分后约 12-16 个子地块 |
| `chunks` | 流式加载单位不变（仍按 50 m chunk），只是每个 chunk 内的对象更多 |
| `minimap` | 按 `EdgeKind::Lane` 用更细的线画巷道 |
| `debug_viz` | 巷道用独立配色 |
| `WorldGrid` | **不改**。`is_road` 仍表示 tier-0 邻接；巷道不进 grid（见下） |
| 存档 | `LayoutBlock.children` 加 `#[serde(default)]`，旧存档读出空 vec = 不细分，向后兼容 |

`WorldGrid` 不进巷道是一个有意的取舍：grid 是"哪些格子邻接街道"的粗粒度查询结构，供存档和快速判定使用；巷道是几何细节，由 `children` 承载。若未来需要逐巷查询，再给 `SubBlock` 加索引，而不是把 grid 的粒度推向 12 m（那会破坏 1:1 的 chunk 对齐）。

## 备选方案

### A. 全局缩小 `CELL_SIZE` 到 12.5 m（已否决）

最直接，但代价最大：

- chunk 与格子 1:1 对齐（`CHUNK_SIZE == CELL_SIZE`），改格子等于改流送系统；
- 合并表全部失衡：公寓 2×2 = 25 m 见方、厂房 4×4 = 50 m——米制尺寸要整体重推；
- 街宽 6-10 m 会吃掉 12.5 m 格子的大半，放置几何崩；
- 4 m 格点抖动的调参依据（`PERTURB_MAX` 的整段推导）失效；
- 外环带、碰撞环裁剪、小地图比例全部要重算；
- `GRID_CELLS` 从 16 涨到 64，`WorldGrid` 变大 16 倍，旧存档失效。

### B. 只给城中村做内部细分（部分采纳，作为第一阶段）

即 ADR-0008 的边界情况：只对 `BlockType::UrbanVillage` 细分，其他街区维持现状。作为**第一阶段**落地，验证细分 pass 的几何与放置正确性，再推广到老城/公寓。本 ADR 的参数表已覆盖三种类型，实现时用开关控制。

### C. 无差别全域细分（已否决，原型实测）

2026-11-16 的 Python 原型第一版：对整张图统一按 7-8.6 m 房排 + 3 m 巷无限细分。结果：

- 街区的尺寸差异被抹平（全图都是同一种条纹），视觉上像**编织篮纹**；
- 完全没有道路等级差别——玩家分辨不出主干和巷子；
- 路网密度虽然上去了，但"自然度"反而下降。

**结论：细分必须按街区类型走，层级差异正是自然感的来源。**

### D. 房排内部随机切口（已否决，原型实测）

原型第二版在每条房排内部做了随机切口，想制造不规则地块。结果：切出来的巷子是**互不连通的碎片**，渲染出来是一片散落的死胡同短线，比不切更糟。

**结论：巷道必须贯穿街区某一维度，只在端点与 tier-0 相交形成 T。不规则性来自切分位置和主轴方向的随机，而不是来自把巷子打断。**

## 后果

### 需要实现

- `layout_graph.rs`：`SubBlock` / `SubFrontage` / `EdgeKind` 结构，`LayoutBlock.children` 字段；
- `path_network.rs`：细分 pass（按街区类型分发参数），巷道的 `LayoutEdge` 生成，`EdgeKind` 标注；
- `placement.rs`：放置目标从 `block.polygon` 改为遍历 `block.children`（空则回退到街区本体）；
- `collision.rs`：棱柱按子地块生成；
- `minimap.rs` / `debug_viz.rs`：巷道线宽与配色；
- 测试：细分的确定性、子地块不重叠、巷宽在区间内、T 路口计数 > 0、旧存档 serde 兼容。

### 需要验证

- **步行尺度的路口密度**：目标是在 50 m 常规街区内部也每隔 10-24 m 出现一个岔口（现状该区间内为 0）。度量方式：统计"相邻两个节点之间的距离"分布，细分后应有大量 10-24 m 的间隔；
- **巷宽与巷距**：城中村临巷地块最小边 ≥ 4 m（否则放不下 4-7 m 的房子）；
- **碰撞棱柱数量**：城中村街区细分后每个 50 m 街区约 12-16 个，全图棱柱数上升约 3-5 倍，需确认 `CollisionIndex` 的查询性能仍达标；
- **存档**：旧存档（无 `children`）读出后行为与现在完全一致。

### 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 灌入的巷道与 tier-0 街道连接处收口不齐 | 路口处出现缝隙或穿插 | 巷道宽度取 `min(lane_half, edge.width/2)`，端点按街道半宽收口；复用现有 `inset_polygon_clip_with_insets` 的几何验证，并断言子地块不重叠（沿用 `inset_polygons_never_overlap` 的检查方式） |
| 细分后地块过小，建筑行被系统性拒绝 | 城中村出现空地 | `usable_frontage` 已有 "frontage < MIN_FACADE 就跳过" 的保护；需在测试里断言每街区建筑覆盖率下限 |
| 棱柱数量上升拖慢碰撞 | 行走卡顿 | 按 chunk 分桶已存在；若不够，子地块棱柱可合并为每街区一个凸包（视觉上是子地块，碰撞仍按父街区——城中村巷道窄，玩家本来就进不去房排内部） |
| 细分主轴随机导致全图单向条纹 | 路网显得机械 | 原型已验证：主轴随机翻转（30% 概率）+ 按街区类型分级，条纹感消失；把"主轴方向分布"作为回归指标 |

### 分阶段落地建议

1. **第一阶段**：`BlockType::UrbanVillage` 单类型细分，验证几何 + 放置 + 碰撞 + 存档；
2. **第二阶段**：推广到老城（24 m 巷距）；
3. **第三阶段**：公寓（46 m 巷距）+ 小地图与调试可视化收尾。

第一阶段不触碰 tier-0 逻辑，`LayoutGraph` 的既有字段语义不变，是风险最低的落点。
